Fundamentos del scroll

Antes de los efectos, el escenario: cómo el scroll deja de ser "bajar la página" y se convierte en una línea de tiempo que tú controlas.

0.1

Parallax

Capas que se mueven a distintas velocidades. Tu cerebro interpreta "lo que se mueve más rápido está más cerca", y una pantalla plana gana profundidad. Mueve el mouse y haz scroll; luego pulsa Ver las capas.

PROFUNDIDAD

Cómo funciona

  1. Apilas varias capas con position: absolute, cada una con una "profundidad" entre 0 (lejos) y 1 (cerca).
  2. Calculas cuánto ha avanzado la sección en la pantalla: un número de 0 a 1.
  3. Cada capa se desplaza progreso × profundidad. Las cercanas viajan más, las lejanas casi no se mueven.
  4. Usa siempre transform: translate3d(): lo mueve la GPU sin recalcular el layout.

Úsala para portadas, paisajes y fondos con profundidad. Cuidado con exagerar: con más de ~200px de diferencia marea en móviles.

const layers = document.querySelectorAll('[data-depth]');

function update() {
  const r = scene.getBoundingClientRect();
  // 0 cuando la sección entra por abajo, 1 cuando sale por arriba
  const p = (innerHeight - r.top) / (innerHeight + r.height);

  layers.forEach(layer => {
    const depth = +layer.dataset.depth;         // 0 = lejos · 1 = cerca
    const y = (p - 0.5) * depth * -220;
    layer.style.transform = `translate3d(0, ${y}px, 0)`;
  });
  requestAnimationFrame(update);                 // 60 fps, sin 'scroll' events
}
update();

0.2

Secciones fijas y scrollytelling

Un elemento se queda quieto (pinned) mientras el texto pasa a su lado, y cada párrafo cambia lo que muestra el gráfico. Es la base de los reportajes del New York Times y de casi toda landing cinemática.

24 datos

Un anillo de datos

El gráfico está en position: sticky: se queda pegado mientras este texto sube. Sigue bajando.

Se ordenan

Un IntersectionObserver detecta que este párrafo cruzó la mitad de la pantalla y le avisa al gráfico: "paso 2".

Se comparan

Los mismos 24 puntos, en otra posición. Una transición CSS hace el viaje: no hay nada que redibujar.

Se agrupan

El lector controla el ritmo. Si sube, la historia retrocede. Eso es scrollytelling.

Cómo funciona

  1. El contenedor es alto (varios pasos de texto); el gráfico usa position: sticky; top: 0 y se queda fijo mientras el contenedor pasa.
  2. Cada paso de texto se observa con IntersectionObserver, usando la línea central de la pantalla como disparador.
  3. Al activarse un paso, el gráfico recibe un estado nuevo (posiciones, colores) y CSS anima el cambio.
  4. Variante "scrub": en vez de pasos, un progreso continuo 0→1 mueve la animación fotograma a fotograma, como en la landing de Roberto.

Úsala para explicar algo en orden: un producto, un proceso, datos. Cuidado con overflow: hidden en un ancestro: rompe sticky sin avisar.

/* CSS: el gráfico se queda pegado */
.graphic { position: sticky; top: 10vh; height: 80vh; }

/* JS: ¿qué paso cruza el centro de la pantalla? */
const io = new IntersectionObserver(entries => {
  entries.forEach(e => {
    if (e.isIntersecting) setStep(+e.target.dataset.step);
  });
}, { rootMargin: '-50% 0px -50% 0px' });   // línea en el centro

document.querySelectorAll('.step').forEach(s => io.observe(s));

function setStep(i) {
  dots.forEach((dot, k) => {
    const [x, y] = layouts[i][k];
    dot.style.transform = `translate(${x}px, ${y}px)`; // CSS anima
  });
}

0.3

Smooth scroll: inercia

Usa la rueda del mouse (o arrastra con el dedo) en las dos cajas. La de la derecha no salta al destino: lo persigue con suavidad, como una grúa de cine. La gráfica muestra exactamente qué está pasando.

Nativo

Con inercia (lerp)

Posición en el tiempo

nativoobjetivo (rueda)suavizado

Cómo funciona

  1. Se intercepta la rueda y se acumula un objetivo: dónde quiere ir el usuario.
  2. En cada frame, la posición actual avanza un porcentaje de la distancia que falta: actual += (objetivo − actual) × 0.08. Esto se llama lerp (interpolación lineal).
  3. Como siempre falta un poco, frena de forma exponencial: esa es la sensación de inercia.
  4. El contenido se mueve con transform. Sube el factor para que se sienta más firme o bájalo para que flote más.

Úsala para dar peso y calma a sitios de portafolio o de marca. Cuidado con la accesibilidad: respeta prefers-reduced-motion y no rompas el scroll del teclado ni el de los lectores de pantalla. Lenis lo resuelve por ti.

let target = 0, current = 0;
const ease = 0.08;                               // 0.02 = flota · 0.4 = firme

box.addEventListener('wheel', e => {
  e.preventDefault();
  target = clamp(target + e.deltaY, 0, maxScroll);
}, { passive: false });

function raf() {
  current += (target - current) * ease;          // lerp: la magia completa
  content.style.transform = `translate3d(0, ${-current}px, 0)`;
  requestAnimationFrame(raf);
}
raf();

Animaciones con CSS puro: animation-timeline

Lo nuevo de la plataforma: amarras una animación CSS normal al scroll en lugar de al reloj. Cero JavaScript, y corre fuera del hilo principal. Haz scroll dentro de la caja.

Comprobando soporte…
↓ Haz scroll aquí dentro ↓
Aparecer

animation-timeline: view(): la animación avanza mientras el elemento cruza la vista.

Escalar

animation-range: entry 0% cover 40%: empieza al entrar y termina al 40% del recorrido.

Girar en 3D

Es la misma regla @keyframes de siempre. Solo cambió el "reloj".

Revelar con clip-path

Una cortina que se abre de izquierda a derecha, ligada a tu dedo.

Deslizar

Y la barra de arriba usa scroll-timeline: el progreso de toda la caja.

Fin

Todo esto sin una sola línea de JavaScript.

·

Cómo funciona

  1. Escribes un @keyframes normal.
  2. En vez de animation-duration, le das un "reloj" de scroll: scroll() para el progreso de un contenedor, o view() para el paso de un elemento por la vista.
  3. animation-range define en qué tramo del recorrido ocurre (entrada, salida o cobertura).
  4. Envuélvelo en @supports: donde no hay soporte, el contenido simplemente se ve estático.

Úsala para revelados, barras de progreso y parallax sencillo: es la opción más ligera que existe. Cuidado con coreografías complejas (pins, secuencias encadenadas): ahí GSAP sigue siendo más cómodo.

@keyframes aparecer {
  from { opacity: 0; transform: translateY(80px); }
}

@supports (animation-timeline: view()) {
  .card {
    animation: aparecer linear both;
    animation-timeline: view();                /* reloj = paso por la vista */
    animation-range: entry 0% cover 40%;
  }

  .barra-progreso {
    transform-origin: left;
    animation: crecer linear both;
    animation-timeline: scroll(root);          /* reloj = scroll de la página */
  }
}
@keyframes crecer { from { transform: scaleX(0); } }

Soporte: Chrome/Edge 115+, Safari 26+. En Firefox todavía hay que activarlo manualmente, así que úsalo como mejora progresiva.

La tarjeta gráfica dibuja millones de píxeles por segundo. Estas técnicas la ponen a trabajar directamente desde el navegador.

1.1

Cámara 3D guiada por scroll

Una escena 3D real hecha con Three.js. El scroll no mueve la página: mueve la cámara sobre una curva invisible (el mapa de la esquina la muestra). Sigue bajando.

Paso 1 · La curvaSe definen 7 puntos en el espacio y CatmullRomCurve3 traza una curva suave que pasa por todos.

Paso 2 · El scroll es "t"El progreso del scroll (0→1) elige un punto de la curva: curve.getPointAt(t). Ahí va la cámara.

Paso 3 · Mirar adelanteLa cámara mira un punto un poco más adelante en la misma curva, así "gira" sola en cada curva.

Paso 4 · ProfundidadLa niebla, las luces de colores y la rejilla del suelo venden la distancia. Sin ellas se vería plano.

t = 0.000

Cómo funciona

  1. Three.js prepara lo básico: Scene, PerspectiveCamera y WebGLRenderer sobre un canvas.
  2. Una curva 3D define el recorrido de la cámara, como el riel de un dolly de cine.
  3. El progreso del scroll se suaviza con lerp y se usa como t en la curva.
  4. La cámara se coloca en t y mira hacia t + 0.02, así sigue la dirección del camino.

Úsala para presentar un producto, un mundo o una marca como un viaje. Cuidado con el peso: modelos grandes, texturas 4K y sombras pueden tumbar un celular. Usa glTF comprimido (Draco) y limita el pixelRatio a 2.

import * as THREE from 'three';

const curve = new THREE.CatmullRomCurve3([
  new THREE.Vector3(0, 1, 18),
  new THREE.Vector3(6, 2, 8),
  new THREE.Vector3(0, 3, -2),
  // … más puntos
]);

let t = 0;
function render() {
  const target = scrollProgress(section);          // 0 → 1
  t += (target - t) * 0.08;                        // suavizado

  camera.position.copy(curve.getPointAt(t));
  camera.lookAt(curve.getPointAt(Math.min(t + 0.02, 1)));

  renderer.render(scene, camera);
  requestAnimationFrame(render);
}

1.2

Partículas que forman figuras

Miles de puntos, y cada uno sabe a dónde ir. Cambia de figura con los botones y pasa el mouse (o el dedo) por encima para empujarlos.

0 partículas

Cómo funciona

  1. Para cada figura se calcula una lista de posiciones destino, una por partícula. El texto se obtiene dibujándolo en un canvas oculto y leyendo qué píxeles quedaron pintados.
  2. En cada frame, cada partícula recorre un porcentaje de la distancia a su destino (el mismo lerp del smooth scroll). Cada una tiene su propia velocidad, así el movimiento se siente orgánico.
  3. El mouse se proyecta al espacio 3D; las partículas cercanas reciben una fuerza que las aleja.
  4. Todo va en un solo THREE.Points con mezcla aditiva: miles de puntos en una sola llamada de dibujo.

Úsala para heroes con logo, transiciones entre secciones y visualizaciones. Cuidado con pasar de ~20 000 partículas en CPU; más allá conviene moverlas en un shader (GPGPU).

1.3

Shaders: programar píxeles

Un shader es un programa pequeño que la tarjeta gráfica ejecuta para cada píxel a la vez. Este fondo vivo es una sola función que decide un color. Juega con los controles.

Colores

Cómo funciona

  1. Se dibuja un triángulo que cubre todo el canvas. El vertex shader solo lo coloca en pantalla.
  2. El fragment shader corre una vez por píxel, en paralelo: recibe su coordenada (vUv) y devuelve un color.
  3. El "ruido" (simplex noise) da valores suaves y aleatorios. Si le metes el mismo ruido como entrada otra vez (domain warping), aparecen esas formas líquidas.
  4. JavaScript solo envía unos pocos números por frame (uniforms): el tiempo, el mouse y los colores.

Úsala para fondos vivos, texturas generativas y transiciones únicas: pesa unos pocos KB y se ve en 4K. Cuidado con los celulares de gama baja: mide los FPS y baja la resolución del canvas si hace falta.

// Fragment shader (GLSL) — se ejecuta para CADA píxel
precision highp float;
varying vec2 vUv;
uniform float uTime, uWarp;
uniform vec3 uC1, uC2, uC3;

void main() {
  vec2 p = vUv - 0.5;
  // domain warping: ruido dentro de ruido
  vec2 q = vec2(snoise(p * 1.2 + uTime * 0.10),
                snoise(p * 1.2 - uTime * 0.12));
  vec2 r = vec2(snoise(p * 1.5 + q * uWarp + uTime * 0.15),
                snoise(p * 1.5 + q * uWarp - uTime * 0.10));
  float n = snoise(p + r * uWarp * 0.8);

  vec3 col = mix(uC1, uC2, smoothstep(-0.6, 0.6, n));
  col = mix(col, uC3, smoothstep(0.2, 0.9, r.x));
  gl_FragColor = vec4(col, 1.0);
}

2.1

Secuencia de frames por scroll

Las páginas de AirPods o del iPhone no reproducen un video: dibujan una imagen distinta según tu scroll. Aquí se renderizaron 72 imágenes WebP en tu navegador mientras cargaba la página. Baja despacio y luego sube.

  2. Pantalla
  3. Placa

frame 01 / 72 · —

Cómo funciona

  1. Se exporta una animación (3D o video) como decenas o cientos de imágenes numeradas: frame_001.webp, frame_002.webp…
  2. Se precargan todas en objetos Image antes de mostrar la sección. Por eso existen los preloaders (capítulo 6).
  3. Con el progreso del scroll se calcula el índice, Math.round(p × (total − 1)), y se dibuja esa imagen en un canvas.
  4. ¿Por qué no un <video>? Porque saltar a un tiempo exacto (currentTime) es lento e impreciso; una imagen se dibuja al instante y en cualquier dirección.

Úsala para revelar un producto: rotarlo, "explotarlo" en piezas, abrirlo. Cuidado con el peso: 120 frames × 40 KB son ~5 MB. Usa WebP/AVIF, resoluciones distintas para móvil y carga diferida.

const TOTAL = 72;
const frames = [];
for (let i = 1; i <= TOTAL; i++) {
  const img = new Image();
  img.src = `/frames/frame_${String(i).padStart(3, '0')}.webp`;
  frames.push(img);                              // precarga
}

let last = -1;
function draw() {
  const p = scrollProgress(section);             // 0 → 1
  const i = Math.round(p * (TOTAL - 1));
  if (i !== last && frames[i].complete) {
    ctx.drawImage(frames[i], 0, 0, canvas.width, canvas.height);
    last = i;                                    // solo redibuja si cambia
  }
  requestAnimationFrame(draw);
}

Cómo funciona

  1. Detrás está la escena 2. Encima, una capa negra con el texto en blanco y mix-blend-mode: multiply: el negro tapa todo y el blanco deja ver lo que hay atrás. Las letras se vuelven ventanas.
  2. Se mide el centro de la letra "I" y se usa como transform-origin.
  3. El scroll escala la capa de forma exponencial (120^p), para que la aceleración se sienta natural, como un zoom real.

Úsala para pasar de una sección a otra de forma memorable: del logo al contenido, de un capítulo al siguiente. Cuidado con la precisión del origen: si no apuntas al trazo de la letra, entrarás por el negro.

  front.style.transform  = `scale(${Math.pow(120, p)})`;

}

Transiciones entre vistas

Que cambiar de página se sienta como un corte de cámara y no como un parpadeo en blanco.

3.1

View Transitions API

Abre un proyecto: la miniatura "vuela" y se convierte en la portada del detalle. No hay librería: es una función nativa del navegador. Activa la cámara lenta para ver el truco.

—

Cómo funciona

  1. Le das el mismo nombre (view-transition-name: hero) al elemento de "antes" y al de "después".
  2. Llamas a document.startViewTransition(() => cambiarElDOM()). El navegador toma una foto del estado viejo, aplica tu cambio y toma otra del nuevo.
  3. Anima solo entre ambas fotos: cada elemento con nombre viaja de su posición y tamaño viejos a los nuevos, y el resto hace un fundido.
  4. Personalizas todo con CSS: ::view-transition-group(hero), ::view-transition-old(root)…

Úsala para galerías, listas → detalle, pestañas y filtros. Cuidado con repetir el mismo nombre en dos elementos visibles a la vez: la transición se cancela.

function abrir(card) {
  card.querySelector('.thumb').style.viewTransitionName = 'hero';

  document.startViewTransition(() => {
    card.querySelector('.thumb').style.viewTransitionName = '';
    grid.hidden = true;
    detail.hidden = false;
    detail.querySelector('.hero').style.viewTransitionName = 'hero';
  });
}

/* CSS: duración y curva de todas las transiciones */
::view-transition-group(*) {
  animation-duration: .55s;
  animation-timing-function: cubic-bezier(.77, 0, .18, 1);
}

Soporte: Chrome/Edge 111+, Safari 18+ y Firefox 144+. Donde no existe, el cambio ocurre sin animación (mejora progresiva).

3.2

Transiciones entre páginas

Así funcionan Barba.js y Swup: interceptan el clic en un enlace, animan la salida, descargan la página nueva, cambian el contenido y animan la entrada, sin recargar. Navega por este mini sitio y mira las fases a la derecha.

Estilo de transición

  1. leaveAnima la salida de la vista actual
  2. fetchDescarga el HTML de la página nueva
  3. swapReemplaza el contenido y la URL
  4. enterAnima la entrada de la nueva vista

Cómo funciona

  1. Un listener captura los clics en enlaces internos y cancela la navegación normal.
  2. leave: se anima la salida (cortina, fundido…) mientras en paralelo se descarga la página nueva con fetch.
  3. swap: se extrae el contenedor principal del HTML nuevo, se reemplaza el actual y se actualiza la URL con history.pushState.
  4. enter: se anima la entrada. El botón "atrás" también funciona gracias a popstate.

Novedad: las cross-document view transitions hacen esto sin JavaScript en sitios de varias páginas: basta una regla CSS en ambas páginas. Cuidado con los scripts de cada página: al no recargar, hay que reiniciarlos a mano en el hook enter.

// Barba.js — patrón leave / enter
barba.init({
  transitions: [{
    async leave({ current }) {
      await gsap.to(curtain, { clipPath: 'inset(0 0 0 0)' });
    },
    async enter({ next }) {
      await gsap.to(curtain, { clipPath: 'inset(0 0 100% 0)' });
      gsap.from(next.container.children, { y: 30, opacity: 0, stagger: .06 });
    },
  }],
});

04

Tipografía animada

Las letras también actúan. Con poco código, el texto deja de ser decoración y se vuelve personaje.

4.1

Texto que se descifra

Las letras aleatorias se "hackean" hasta formar la palabra. Pasa el mouse por las palabras verdes o escribe tu propio mensaje. Por cierto, el título del encabezado usa el mismo efecto cada vez que cambias de sección.

ACCESO CONCEDIDO_

Pasa el mouse por SISTEMA, por PROTOCOLO o por CLASIFICADO para volver a descifrarlos.

Cómo funciona

  1. A cada letra se le asigna al azar un frame de inicio y uno de fin.
  2. Antes de su inicio muestra la letra vieja; entre inicio y fin, un símbolo aleatorio que cambia de vez en cuando; al final, la letra correcta.
  3. Como cada letra termina en un momento distinto, la palabra "se resuelve" de forma orgánica y no toda de golpe.
  4. Los símbolos en proceso llevan otro color (.dud) para que se lea el "cálculo".

Úsala para etiquetas, menús, títulos cortos y estética tech o sci-fi. Cuidado con los lectores de pantalla: pon el texto final en aria-label y no lo uses en párrafos largos.

const CHARS = '!<>-_\\/[]{}—=+*^?#01';

function scramble(el, text) {
  const queue = [...text].map(to => {
    const start = Math.random() * 20 | 0;
    return { to, start, end: start + 8 + (Math.random() * 25 | 0) };
  });
  let frame = 0;
  (function tick() {
    let done = 0;
    el.innerHTML = queue.map(q => {
      if (frame >= q.end) { done++; return q.to; }
      if (frame >= q.start)
        return `<span class="dud">${CHARS[Math.random() * CHARS.length | 0]}</span>`;
      return '';
    }).join('');
    if (done < queue.length) { frame++; requestAnimationFrame(tick); }
  })();
}

Cómo funciona

Marquesina que siente tu scroll

Texto gigante en bucle infinito. Cuando haces scroll acelera, se inclina y cambia de dirección si subes. Pruébalo con fuerza.

WebGL · Shaders · Partículas · Luz ·

velocidad del scroll: 0 px/frame

Cómo funciona

  1. El texto se duplica dentro de una pista. Cuando la primera copia sale por completo, la posición vuelve a 0 con un módulo (x % ancho) y el salto no se nota.
  2. Cada frame se mide la velocidad del scroll: scrollY − scrollYAnterior, suavizada.
  3. La velocidad base se suma a la del scroll, y la dirección sigue el signo del scroll.
  4. Un skewX proporcional a la velocidad da la sensación de "viento".

Úsala para separadores entre secciones, listas de clientes y lemas. Cuidado con el contenido importante: lo que se mueve sin parar no se lee. Pausa si hay prefers-reduced-motion.

let x = 0, dir = 1, lastY = scrollY, vel = 0;

function tick() {
  const dy = scrollY - lastY; lastY = scrollY;
  vel += (dy - vel) * 0.1;                        // velocidad suavizada
  if (Math.abs(vel) > 0.5) dir = Math.sign(vel);

  x -= (1 + Math.abs(vel) * 0.8) * dir;
  const w = track.children[0].offsetWidth;        // ancho de una copia
  x = ((x % w) - w) % w;                          // bucle sin costura

  track.style.transform = `translate3d(${x}px,0,0) skewX(${skew}deg)`;
  requestAnimationFrame(tick);
}

5.3

Imágenes que se distorsionan

La imagen no es un <img>: es una textura dentro de un shader. Cada píxel decide de qué parte de la imagen tomar su color según la distancia al cursor. Pasa el mouse y cambia de efecto.

Cómo funciona

  1. La imagen se sube a la GPU como textura. El fragment shader la lee con texture2D(uTex, uv).
  2. En lugar de leer en uv, lee en uv + desplazamiento. El desplazamiento depende de la distancia al mouse y se desvanece con smoothstep.
  3. Ola: un seno de la distancia. Vidrio: atrae los píxeles hacia el cursor, como una lupa. RGB split: lee rojo, verde y azul en posiciones ligeramente distintas.
  4. La intensidad crece con la velocidad del mouse y se apaga al salir: un lerp en JS, un uniform en el shader.

Úsala para galerías de proyectos, portadas y hovers de tarjetas. Cuidado con crear un contexto WebGL por imagen: usa uno solo que dibuje todas.

uniform sampler2D uTex;
uniform vec2 uMouse;           // 0 → 1
uniform float uStrength, uTime;
varying vec2 vUv;

void main() {
  vec2 d = vUv - uMouse;
  float dist = length(d);
  float fall = smoothstep(0.35, 0.0, dist) * uStrength;

  // Ola: los píxeles se desplazan en círculos concéntricos
  vec2 offset = normalize(d) * sin(dist * 40.0 - uTime * 6.0) * 0.02 * fall;

  // RGB split: cada canal se lee en un lugar distinto
  vec2 s = d * fall * 0.25;
  vec3 col = vec3(texture2D(uTex, vUv + offset + s).r,
                  texture2D(uTex, vUv + offset).g,
                  texture2D(uTex, vUv + offset - s).b);
  gl_FragColor = vec4(col, 1.0);
}

Sonido y sentidos

Lo inmersivo no es solo visual. Un sonido sutil o una vibración a tiempo convierten un clic en algo físico. Todo el audio de esta página se genera en vivo: no hay un solo archivo MP3.

7.1

Sonidos de interfaz

Toca cada pad. Todos son osciladores sintetizados en el momento. Si activas ♪ Sonido en el encabezado, los botones de toda la página harán "tick" al pasar el mouse.

Consejo: úsalos al 10–20 % de volumen, cortos y siempre con opción de apagarlos. Los navegadores bloquean el audio hasta el primer clic del usuario.

Cómo funciona

  1. Se crea un AudioContext (solo después de un clic: es regla del navegador).
  2. Un OscillatorNode genera un tono (seno, cuadrada, sierra); un GainNode controla el volumen.
  3. La "forma" del sonido es la envolvente: el volumen sube en 5 ms y cae de forma exponencial. Si además la frecuencia baja, suena a "clic"; si sube, a "éxito".
  4. El whoosh es ruido blanco pasando por un filtro cuya frecuencia se desliza, como el viento.

Úsala para juegos, apps creativas, confirmaciones importantes. Cuidado con activarlo por defecto: casi todo el mundo navega en silencio o en público.

const ac = new AudioContext();

function tone({ f = 880, f2, type = 'sine', dur = 0.08, vol = 0.2 }) {
  const t = ac.currentTime;
  const osc = ac.createOscillator();
  const gain = ac.createGain();
  osc.type = type;
  osc.frequency.setValueAtTime(f, t);
  if (f2) osc.frequency.exponentialRampToValueAtTime(f2, t + dur);

  gain.gain.setValueAtTime(0, t);
  gain.gain.linearRampToValueAtTime(vol, t + 0.005);         // ataque
  gain.gain.exponentialRampToValueAtTime(0.0001, t + dur);  // caída

  osc.connect(gain).connect(ac.destination);
  osc.start(t); osc.stop(t + dur);
}

const click   = () => tone({ f: 520, f2: 260, type: 'triangle', dur: .07 });

Cómo funciona

  1. La fuente de audio (un loop, un <audio> o el micrófono) se conecta a un AnalyserNode.
  2. Cada frame, getByteFrequencyData() llena un arreglo con la energía de cada frecuencia (0–255). Es una FFT hecha por el navegador.
  3. Se agrupan en bandas (graves, medios, agudos) y cada una controla una propiedad visual.
  4. El micrófono pasa por el analizador pero no por los altavoces, para evitar el eco.

Úsala para sitios de música, eventos, podcasts y experiencias artísticas. Cuidado con pedir el micrófono sin explicar por qué: siempre detrás de un botón claro.

const analyser = ac.createAnalyser();

source.connect(analyser);                   // loop, <audio> o micrófono

const avg = (a, b) => {
  let s = 0; for (let i = a; i < b; i++) s += data[i];
  return s / (b - a) / 255;                 // 0 → 1
};

function draw() {
  analyser.getByteFrequencyData(data);
  const bass = avg(1, 6), mid = avg(6, 48), high = avg(48, 200);

  core.radius = 60 + bass * 80;             // el núcleo late con el bombo
  core.hue    = 200 + mid * 120;
  rays.alpha  = 0.3 + high * 0.7;
  requestAnimationFrame(draw);
}

Cómo funciona

  1. En el editor de Rive defines estados (idle, hover, press…), cada uno con su animación.
  2. Defines entradas: booleanos (isHover), números (progress) y disparadores (celebrate).
  3. Dibujas transiciones entre estados con condiciones ("si isPressed es true, ve a press") y mezclas suaves.
  4. Desde tu código solo cambias las entradas; la animación decide sola cómo llegar ahí. Su runtime (WASM + canvas) es muy eficiente.

Úsala para personajes, botones con personalidad, onboarding interactivo y juegos ligeros. Frente a Lottie: Rive es interactivo por diseño y sus archivos pesan todavía menos; Lottie tiene más ecosistema y animaciones listas para usar.

import { Rive } from '@rive-app/canvas';

const r = new Rive({
  src: '/personaje.riv',
  canvas: document.querySelector('#rive'),
  stateMachines: 'Main',
  autoplay: true,
  onLoad: () => {
    const inputs = r.stateMachineInputs('Main');
    const isHover   = inputs.find(i => i.name === 'isHover');
    const celebrate = inputs.find(i => i.name === 'celebrate');

    canvas.onpointerenter = () => isHover.value = true;
    canvas.onpointerleave = () => isHover.value = false;
    boton.onclick         = () => celebrate.fire();   // trigger
  },
});
